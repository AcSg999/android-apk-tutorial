# 14 · 验证范围与维护记录

[返回目录](../README.md) · [上一章](13-troubleshooting.md) · [官方资料](sources.md)

本仓库定位为通用教程。环境、构建工具与依赖由读者在自己的电脑上安装；示例源码只是帮助理解和复现流程，不附带可安装 APK、工具分发包或预装依赖。

## 14.1 文档与辅助代码检查

维护者可以在教程仓库根目录，使用自己安装的 Python 3 执行：

```powershell
python -B scripts/check-tutorial.py
python -B -m unittest discover -s extras/network-lab -p "test_*.py" -v
```

第一条检查 Markdown 的本地链接、代码围栏、示例 Android XML、必要文件，以及是否混入 JAR、APK、密钥等不应分发的文件。第二条实际启动本地 HTTP 服务，验证健康接口、中文 JSON 与未知路由。

这些检查无需下载依赖，也不代表 Android 应用已经编译或通过真机测试。它们用于维护教程完整性。

2026-10-20 的实际检查结果：文档本地链接、代码围栏、示例 XML 与无二进制 / 密钥检查通过；本地 API 的 3 个测试通过；可选发布脚本通过 PowerShell 语法解析检查。外部链接与市场流程仍应在使用时重新核验。

## 14.2 Android 参考源码的验证边界

当前参考源码**尚未完成完整 Android 构建与设备验证**。编写期间曾确认固定 Gradle 版本可由 JDK 17 启动；尝试完整构建时，Google Maven 的 TLS 握手失败，未进入 Kotlin 编译与测试，而且本机未配置 Android SDK。因此没有可以宣称“已验证可安装”的构建产物。

读者应按第 02—04 章自行安装和创建项目，再运行：

```powershell
./gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

这条命令在**读者自己的 Android 项目根目录**执行，而不是教程仓库。成功后还需要按 [真机验收](03-first-run.md)、[产品质量](06-product-quality.md) 和 [签名升级](07-signing-and-updates.md) 实测。

维护者只有在完成以下证据后，才应更新为“已完成端到端验证”：

- 构建环境版本与成功日志。
- 单元测试和 Lint 报告。
- 至少最低 / 目标系统与真实设备的主流程记录。
- 正式包签名验证、真实下载地址、覆盖更新保留数据的测试。

## 14.3 示例当前的功能边界

- 包含：小型离线待办、本机保存、筛选、完成、删除确认、基础错误状态、深色模式。
- 不包含：账号、云同步、导出 / 导入、通知提醒、支付、市场接入或所有应用类型的实现。
- 数据存储：小列表通过 Preferences DataStore 保存 JSON，限制 200 项，复杂产品应采用适合的数据方案。
- 布局：面向常规手机与字号，极大字体或小屏横屏可能需要进一步调整。
- 网络实验：只说明请求响应链路，不是生产后端或安全认证系统。
- 发布模板：必须由读者填入真实主体、地址、版本、政策内容并自行发布。

## 14.4 更新教材时怎样避免过期

1. 更换依赖时，成组核对 Kotlin、Compose 插件、BOM、AGP、Gradle 与 JDK。
2. 重新执行构建与真机测试，不因“版本号更高”就默认兼容。
3. 更新所有正文与模板中的版本引用，避免半篇旧配置半篇新配置。
4. 市场提交前重新核对官方目标 API、身份验证、测试与数据政策。
5. 给政策记录核验日期，给已验证环境记录真实版本，不填“所有电脑都能用”。

本次资料核验日期为 2026-10-20。未来读者如果看到控制台与教材不同，先查 [官方资料](sources.md)，再按原理判断变化发生在哪一层。
