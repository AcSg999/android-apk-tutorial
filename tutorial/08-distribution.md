# 08 · 让别人真的下载并安装

[返回目录](../README.md) · [上一章](07-signing-and-updates.md) · [下一章：联网与后端](09-network-and-backend.md)

## 8.1 先决定给谁下载

| 场景 | 建议方式 | 是否自动更新 |
| --- | --- | --- |
| 自己测试 | Run / adb 安装 | 不会，重新安装 |
| 同一 Wi-Fi 的少量设备 | 临时局域网文件服务 | 不会 |
| 公开开源项目 | GitHub Releases 附件 | 不会，用户下载新版 |
| 面向普通用户的官网 | HTTPS 下载站 + 对象存储 / CDN | 需要另做更新提示 |
| 大范围用户与商店搜索 | 应用市场 | 按市场更新机制 |

对象存储可以理解为按文件保存并通过 URL 访问的服务；CDN 是把文件分发到更靠近用户的节点以改善下载。静态文件托管不等于业务后端。

## 8.2 先做一次局域网下载验证

仅在可信私人局域网中练习。要求已经生成 `dist/pocket-tasks.apk`，电脑已安装 Python 3。打开一个终端：

```powershell
python -m http.server 8080 --bind 0.0.0.0 --directory dist
```

命令只暴露 `dist` 目录，不要在包含密钥或私人文件的目录开启文件服务。`0.0.0.0` 表示监听本机各网络接口，不是手机要输入的地址。

在另一个 PowerShell 运行 `ipconfig`，找到当前 Wi-Fi 的 IPv4 地址，例如 `192.168.1.23`。手机连接同一个 Wi-Fi，在浏览器访问：

```text
http://192.168.1.23:8080/pocket-tasks.apk
```

这里的 IP 是示例，替换成真实值。Windows 如弹出防火墙请求，只在你确认的私人网络范围允许；不要为这个练习开放路由器公网端口。

下载后点击 APK，按系统提示允许**发起安装的浏览器或文件管理器**安装未知应用。仅对你信任的文件操作，测试完成可关闭该来源权限。

电脑终端按 `Ctrl+C` 结束服务。这个链接只在电脑开机、服务运行、网络可达时有效，不是永久公网下载链接。

若下载到 HTML 而非 APK，通常复制了目录页或错误页地址。检查文件扩展名、大小与 SHA-256。

## 8.3 GitHub Releases：有固定地址的发布附件

以下操作由你在 GitHub 上执行。教程不会创建远程仓库或自动公开本地文件。

1. 创建你控制的仓库。若希望陌生用户无需授权下载，使用适合公开的仓库，先检查源码与素材公开范围。
2. 推送已检查的源码，确认 `.jks`、密码等未进入历史。
3. 完成本地正式包回归和升级测试。
4. 在仓库页面找到 `Releases → Draft a new release`。
5. 创建标签，例如 `v1.0.0`，关联到这次构建的源码提交。
6. 填写改动、最低系统版本、已知限制、APK 摘要和安装说明。
7. 上传 `dist/pocket-tasks.apk` 与 `dist/SHA256SUMS.txt`。AAB 不是提供给浏览器安装的主附件。
8. 检查是草稿、预发布还是正式发布，确认无误后发布。
9. 在手机浏览器或未登录窗口实际打开附件链接，下载并安装。

固定版本附件链接格式：

```text
https://github.com/你的账号/你的仓库/releases/download/v1.0.0/pocket-tasks.apk
```

最新正式发布附件链接格式：

```text
https://github.com/你的账号/你的仓库/releases/latest/download/pocket-tasks.apk
```

把账号、仓库、标签全部换成真实值；这些不是本仓库已经存在的下载地址。最新链接要求最新正式 Release 附件仍使用**完全相同的文件名**，并正确设置 Latest Release。预发布和草稿的行为不同。

不要把 `github.com/.../blob/...apk` 的源码浏览页面当作二进制下载链接。也不要把 APK 放进普通源码提交来代替每版发布附件。

参见 [GitHub 发布链接文档](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)。不同网络环境的可达性差异很大，面向国内用户要实测，必要时选择适合目标地区的合规托管。

## 8.4 做一个自己的下载页

仓库附带 [下载页 HTML 模板](../templates/download-page.html)。复制到专用静态站点目录并命名为 `index.html`，再放入同名 `pocket-tasks.apk`。它是静态文件模板，不会自己上传或签名 APK。

1. 修改名称、版本、文件大小、系统要求、更新记录与联系渠道。
2. 将按钮指向经过验证的 HTTPS APK 地址；若 APK 同目录，则可用模板的相对路径。
3. 把隐私政策转换为公开可阅读的网页，补上链接。
4. 选择静态托管、对象存储，或你自己的 Web 服务器。
5. 开启 HTTPS，确认证书和域名有效。
6. 确认 `.apk` 文件按二进制交付，可使用 `application/vnd.android.package-archive`；必要时设置下载用的 `Content-Disposition`。
7. 手机上实测下载、文件摘要和安装。二维码只是 URL 的另一种表现形式，先验证链接再制作。

下载站建议采用 `/releases/1.0.0/pocket-tasks.apk` 等不可变版本路径。更新“最新版”入口时指向新路径，减少缓存误发旧包。不要悄悄替换旧版本同一 URL 的内容。

下载 APK 属于浏览器的操作，不能让网页绕过系统确认静默安装。若在微信等内置浏览器中被拦截，可引导用户在系统浏览器打开，不应要求关闭整体安全防护。

## 8.5 不装本地 SDK，也能借 CI 构建测试包

CI 即持续集成：远程机器在每次代码更新后按固定步骤构建、检查，并保留结果。它不自动证明应用可用，也不代替发布签名。

本仓库提供 [Android 工作流模板](../templates/android.yml)。将它复制到**你自己的 Android 应用仓库**的 `.github/workflows/android.yml`，按项目版本调整后，才会安装固定 SDK、运行测试和 Lint、构建 Debug APK 并保存 Artifact。本教程仓库不自动执行 Android 构建。

使用步骤：

1. 将自己的 Android 工程和调整后的工作流推送到自己的 GitHub 仓库。该应用仓库应包含在自己电脑生成并核验过的 Wrapper 启动脚本与 JAR，不能只上传本教程的参考文本。确认依赖与 SDK 许可、GitHub 使用条款适合你的用途。
2. 打开 `Actions`，必要时启用工作流。
3. 选择 `Build Android debug APK → Run workflow`。
4. 打开这次运行，看每个步骤是否绿色。
5. 在 Artifacts 下载 `pocket-tasks-debug`，解压得到 APK。
6. 真机安装，并执行功能验收。

**Artifact 是临时构建结果，Release 附件是面向版本发布的分发材料。** Artifact 下载可能需要登录和访问权限，本工作流只保留 14 天；不要把运行页面当作永久公开下载链接。

工作流仅构建 Debug，不使用发布密钥、不上传市场、不创建 Release。不同 CI 机器可能使用不同调试密钥，跨次下载的 Debug APK 因此可能不能覆盖安装；调试时卸载会丢数据，不要把这种机制用于正式更新。

想自动生成正式包时，再将密钥放在 CI 加密 Secrets，限制可触发的分支与环境，采用受控发布；不要给来自陌生 Fork 的 PR 暴露正式密钥。Actions 用量和托管费用以你的账户当前规则为准。

## 8.6 下载以后怎样让用户更新

最简单的第一版：下载页显示新版本与更新记录，用户主动下载并覆盖安装。

进阶可以做一个 HTTPS 版本清单，字段包括 versionCode、versionName、APK URL、文件摘要、最低兼容系统和是否建议更新。客户端比较 versionCode，弹出提示并转交浏览器下载；不要声称无需用户确认即可安装。

更新清单不能替代系统签名校验。保留老版本下载与明确说明；应用市场更新用市场支持的机制，不要给所有渠道强推同一个外部 APK。

## 8.7 2026 年分发需要额外核对开发者验证

不能把“APK 可以自行托管”理解为所有地区所有设备永远只有“未知来源”一个门槛。Android 开发者身份验证与应用登记正在分地区、分渠道实施，官方时间表包含 2026-09-30 的首批保护与后续扩展。

发布前阅读 [Android developer verification](https://developer.android.com/developer-verification) 与 [官方常见问题](https://support.google.com/android-developer-console/answer/16561738)，按你的国家、渠道、认证设备范围选择账号与登记路径。只在 Play 外分发与同时使用 Play 的控制台入口不同。

保留包名、签名证书和开发者身份材料。身份验证不是商店内容审核，也不能用一份地区规则推断中国所有厂商的安装行为。个人 ADB 开发测试与面向大众的下载分发也应分别看待。

## 8.8 本章最后一次实测

请让另一台手机在浏览器访问你发布的链接，不连接开发电脑，完成下载、安装、添加任务。再发布一个更高 versionCode 的包，从同一入口下载更新，验证旧数据保留。

通过这两次测试，你才真正走通“别人能下载使用”的闭环。
