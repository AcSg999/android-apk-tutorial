# 12 · 国内应用市场、备案与长期运营

[返回目录](../README.md) · [上一章](11-google-play.md) · [下一章：排障](13-troubleshooting.md)

国内发布涉及具体主体、服务内容、地区、市场和运营方式。本章提供核验步骤，不把某一家市场要求等同于所有平台要求。涉及准入与资质判断时，以主管机关、接入服务商及目标市场当前规则为准。

## 12.1 先确定目标渠道与设备

常见渠道有华为、小米、OPPO、vivo、腾讯应用宝等。各平台的账号类型、应用分类、上传格式、资质和审核标准可能不同。

华为生态还要先区分目标设备是否支持 Android APK。**原生 HarmonyOS 应用与 Android APK 并非同一种产物**，需要对应工具、工程和发布路线，不能把 APK 当成所有鸿蒙设备均可安装的通用包。

初次发布先选一个与你目标用户匹配的 Android 市场跑通，再扩展其他渠道。不要同时处理五个平台的不同审核反馈。

## 12.2 准备应用与主体资料

| 类别 | 可能需要的内容 | 怎样准备 |
| --- | --- | --- |
| 主体 | 身份或企业资料、联系信息 | 按真实运营主体注册并核验 |
| 应用身份 | 名称、包名、图标、签名证书信息 | 发布前固定，资料保持一致 |
| 版权 | 软件著作权登记、授权书、素材许可等 | 按市场、类目和主体要求准备 |
| 业务资质 | 新闻、出版、医疗、金融、游戏等适用材料 | 先确认准入，再开发与提交 |
| 备案 | 按适用要求完成 APP 与相关服务备案 | 与接入服务商及主管机关核验 |
| 产品 | 安装包、截图、描述、测试账号 | 正式签名包，核心流程完整 |
| 隐私 | 政策、权限理由、SDK 清单、删除渠道 | 与实际代码和数据行为一致 |

不要宣称“所有应用一律必须先申请某一种证书”，也不要宣称“只要离线就能免去每个市场的所有资料要求”。平台审核材料与法律适用范围是不同问题。

## 12.3 APP 备案、网站备案、版权登记不是同一件事

- **APP 备案**：移动互联网应用提供相关互联网信息服务时的备案流程。
- **网站 / 域名与接入相关备案**：与你的网站、域名、服务器接入及部署地区有关，需要按实际情况核对。
- **软件著作权登记**：版权相关证明，不是应用市场内容审核或行政许可的替代品。
- **市场审核**：某个平台是否允许上架。
- **行业前置审批或经营许可**：特定业务可能另行适用。

工信部已经发布 [开展移动互联网应用程序备案工作的通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)。不要仅凭是否在商店上架判断是否适用；自行提供下载也不自动排除备案或其他业务要求。

对纯离线、无互联网信息服务的工具，应带着实际功能、权限、SDK 和服务说明向目标市场 / 服务商确认分类。不要把一句“我没有服务器”当作全部依据，第三方 SDK 也可能联网。

## 12.4 备案资料准备流程

1. 固定应用名称、图标、Android 包名与运营主体。
2. 生成并长期保管正式签名密钥。
3. 记录应用使用的域名、后端服务与接入信息。
4. 向接入服务商或适用平台的备案入口了解材料和核验方式。
5. 按实际要求填应用公钥、证书信息、签名摘要等字段。
6. 提交真实材料，完成身份、短信或其他核验。
7. 审核通过后，按要求在应用或服务中展示备案信息并维护变更。

官方表格涉及包名、公钥、MD5 等字段，可参考 [主管部门备案登记说明](https://xzca.miit.gov.cn/bsfw/bszn/art/2024/art_5d3cc7f452c04fdd97b6881a20b656f9.html)。**这里的证书摘要或公钥信息，不等于 APK 文件的 SHA-256。** 按表单和接入服务商说明提取，不能随便填一个“看起来像哈希”的字符串。

如果换包名、签名、域名、主体或重要服务，先评估是否需要变更备案与市场资料，再发布。

## 12.5 以一家市场为例的通用提交顺序

1. 访问目标市场官方开发者中心，确认真实域名。
2. 注册与认证主体，阅读支持的应用类型和审核规范。
3. 创建应用，填写名称、分类、包名等身份字段。
4. 按要求提交版权、备案与业务材料。
5. 上传正式签名 APK 或平台当前支持的其他格式，不上传 Debug 包。
6. 填写描述、截图、权限用途、隐私政策、SDK 与测试入口。
7. 提交审核，依据具体反馈修复，而不是盲目换壳重传。
8. 通过后在真实目标手机上通过市场安装，再测一次核心功能与升级。

可从 [OPPO 官方发布说明](https://open.oppomobile.com/new/developmentDoc/info?id=10035) 理解一条具体流程，再到自己选择的市场查看当前规则。不同市场的时间、材料和字段不照抄。

## 12.6 隐私检测经常卡在哪里

- 政策写“不收集”，但广告或统计 SDK 在首次打开时已发送设备数据。
- 用户拒绝非必要权限后，整个无关功能也不可用。
- 请求位置、通讯录、所有文件等权限，却没有对应的核心功能理由。
- 隐私政策的主体、应用名称、SDK 清单、联系渠道与安装包不一致。
- SDK 在用户完成适用告知与同意前就初始化并开始处理数据。
- 登录、注销、删除数据、撤回同意等路径不存在或不能实际完成。

解决顺序：先删掉不需要的 SDK 和权限，再梳理真实数据流，最后调整页面与文字。不要只在启动页加一个弹窗却不改变数据处理行为。无需处理某类数据时，也不必为了套模板强行设计无意义的授权。

## 12.7 预算怎样估算

不把“开发工具免费”误解为整个产品没有成本。

| 成本项 | 离线工具 | 联网产品 | 核验方式 |
| --- | --- | --- | --- |
| 开发电脑与测试设备 | 需要 | 需要 | 可先使用现有设备 |
| 域名与下载托管 | 可选 | 常见 | 看地区、流量、HTTPS 与额度 |
| 后端与数据库 | 不需要 | 常见 | 测试最低配置与扩容费用 |
| 短信、地图、OCR、AI | 按功能 | 按调用计费较常见 | 各服务当前价目与免费额度 |
| 开发者账号与材料 | 按渠道 | 按渠道 | 各平台官方要求 |
| 维护与支持 | 需要时间 | 需要更多时间 | 给自己留每月维护预算 |

先定义：`S` 是 APK 大小，单位 MB；`D` 是一个月下载次数。忽略协议开销与缓存命中差异，分发流量约为 `S × D / 1000 GB`（按十进制换算）。例如 30 MB × 1000 次约 30 GB。

这个公式估算数据量，不直接等于账单。实际费用还与 CDN、出站计费、请求次数、免费额度等有关。

## 12.8 长期维护清单

- 每次发布：构建记录、证书指纹、APK 摘要、测试结果、更新说明。
- 定期：核对 API 政策、依赖漏洞与维护状态、SDK 数据行为、域名续费。
- 有后端：检查备份并实际恢复，更新证书与服务，监控错误和费用。
- 用户反馈：记录可复现步骤，保护个人信息，及时告知已知故障。
- 人员变化：回收不再需要的访问权限，保证主体账号和密钥归属清楚。
- 停止服务：提前告知，提供适用的数据导出 / 删除路径，处理域名与服务器退役。

到这里，“做出一个 APK”已经扩展为可持续交付的产品流程。你可以只发布一个离线工具，但应知道何时引入了新的责任与技术系统。
