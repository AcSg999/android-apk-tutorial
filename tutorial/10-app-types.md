# 10 · 换一种应用，需要多学什么

[返回目录](../README.md) · [上一章](09-network-and-backend.md) · [下一章：Google Play](11-google-play.md)

本章给出按功能拆分的实施路线。它不是声称一份待办源码已经实现下面所有应用；每类都有自己的最小版本、技术增量与验收条件。

## 10.1 用同一组问题拆任何应用

1. 核心输入是什么：文字、图像、位置、传感器还是网络？
2. 最重要的状态是什么，放手机还是服务器？
3. 用户退出或断网后，哪些状态必须保留？
4. 谁有权读写数据，失败如何提示？
5. 操作是否产生费用、不可逆结果或外部影响？
6. 必须使用哪些硬件、权限、第三方 SDK 与行业资质？

优先把“最危险或最不确定的一步”做成小实验。例如先验证蓝牙协议能连通，再做漂亮仪表盘；先测模型在目标手机速度，再设计长篇聊天界面。

## 10.2 离线工具：计算器、习惯打卡、记账

**最小版本：** 输入 → 校验 → 计算 / 保存 → 历史记录。

- 技术增量：复杂记录使用 Room；导出使用系统文件选择器。
- 记账金额用整数最小货币单位或精确十进制，不用 Float 存实际金额；还要区分币种与四舍五入规则。
- 打卡涉及日期与时区，午夜、旅行、系统时间变化要测。
- 计算器区分输入表达式、解析规则、数值范围和显示精度。
- 数据恢复比动画优先；重要数据加导出与导入。

验收：重启不丢数据、边界计算正确、导出可重新导入、升级保留记录。

## 10.3 内容、资讯、商品展示

**最小版本：** 列表 → 详情 → 加载 / 错误 / 空状态。

- 增量：网络客户端、分页、图片加载库、缓存。
- 分页是分批读取数据，避免一次下载整个内容库。
- 图片需缩略图、占位、缓存和失败处理，避免大图耗尽内存。
- 版权、内容授权、资讯来源、推送频率和用户反馈渠道需提前确认。
- 外部链接和 HTML 内容不能无条件信任；避免把不可信网页桥接为任意原生能力。

验收：慢网可取消 / 重试，翻页不重复，重进详情有稳定 ID，接口字段缺失不闪退。

## 10.4 登录、社交、共享清单、聊天

**最小版本：** 两个测试账号各自登录，按权限共享一条数据。

- 增量：认证、后端、数据库、实时更新、推送。
- WebSocket 是持久双向通信连接，不等于应用后台可以永远保持在线。
- 聊天需要消息 ID、发送中 / 已发送 / 失败状态、去重、顺序、离线补发。
- 推送只是通知机制，真正数据仍要向可信服务获取。
- 社区需要举报、屏蔽、内容治理、账号删除和运营流程，不只是发帖 UI。
- 国内厂商与 Google 服务在推送可达性上存在差异，目标地区要实测。

验收：A 不能访问 B 私有数据；重复发送不重复入库；退出与注销行为明确；断网重连不乱序。

## 10.5 相机、扫码、图片编辑、OCR

**最小版本：** 选择一张图片 → 显示 → 处理 → 保存或分享。

- 先用系统 Photo Picker 做单图输入；自定义实时相机再学习 CameraX。
- OCR 指把图像中的文字识别为文本；扫码是解析特定编码图案，二者任务不同。
- 增量：CameraX、图像变换、识别引擎，例如 ML Kit 或端侧模型。
- 注意图片方向、EXIF 旋转、分辨率、压缩、临时文件清理。
- 云端识别需要告知上传范围；离线模型可能需要预置或首次下载。
- 分享文件用 FileProvider / 系统内容 URI，不直接暴露私有 `file://` 路径。

验收：权限拒绝、相机被其他程序占用、竖拍横拍、大图、低光、取消选择都能处理。

参考：[Photo Picker](https://developer.android.com/training/data-storage/shared/photopicker)、[CameraX](https://developer.android.com/media/camera/camerax)、[ML Kit](https://developers.google.com/ml-kit)。

## 10.6 地图、定位、运动轨迹

**最小版本：** 用户主动点击定位，显示当前位置和误差范围。

- 位置不是绝对真值，有时间、精度与噪声；不要把经纬度小数位数当成定位精度。
- 前台定位与后台定位是不同权限和政策场景。
- 持续轨迹涉及后台限制、前台服务通知、耗电、进程死亡后的恢复。
- 地图供应商有 API 许可、密钥限制、收费与地区覆盖；坐标系可能不同，混用会偏移。
- 对中国等特定地区，地图与地理信息服务有额外适用要求，按供应商和主管机关规则核对。

验收：无 GPS、室内、近似位置权限、用户拒绝、坐标变化与电量消耗。不要默认申请后台位置。

参考：[Android 定位权限](https://developer.android.com/develop/sensors-and-location/location/permissions)。

## 10.7 蓝牙、串口、IoT、控制应用

**最小版本：** 找到设备 → 连接 → 读取一个已知参数 → 断开。

- BLE 与经典蓝牙不是同一套协议接口。BLE 常通过 service、characteristic 组织数据，可理解为设备暴露的一组读写入口。
- 明确字节序、数据单位、校验、采样率与命令应答；不要只盯着界面数字。
- 增量：蓝牙权限与扫描、GATT、重连状态机、设备协议解析。
- 用状态机描述“未连接 → 扫描 → 连接中 → 就绪 → 故障”，比散落的布尔变量清晰。
- 手机系统调度和无线网络有不确定延迟；涉及机械执行时，保护联锁、急停和核心实时闭环应由合适的设备侧系统保障。

验收：断电、离开距离、重复连接、权限拒绝、错误帧、丢包、重试不重复触发危险命令。

参考：[Android BLE 官方指南](https://developer.android.com/develop/connectivity/bluetooth/ble/ble-overview)。

## 10.8 AI 对话、语音助手、图像生成

### 云端模型

最小链路：手机输入 → 自己的后端 → 模型服务商 → 后端 → 手机。

- 服务商密钥放后端，客户端使用自己应用的用户认证。
- 增量：流式响应、取消、超时、配额、成本限制、内容治理和数据告知。
- 流式响应是分段传回结果，需处理半条消息、断连和最终完成标记。
- 模型生成结果可能错误；高影响操作需要校验与明确用户确认。
- 提示词中的外部文档是数据，不应自动变为系统操作权限。

先定义估算符号：`N` 是一天请求次数；`T_in`、`T_out` 是平均输入 / 输出 token 数；`P_in`、`P_out` 是每百万 token 的价格；金额单位必须一致。token 是模型切分文本的基本片段，不等于一个汉字或一个单词。

```text
日模型费用约为 N × (T_in × P_in + T_out × P_out) / 1,000,000
```

这只覆盖模型 token 计费，不包含缓存、图像 / 音频、搜索、服务器和流量等其他项目。价格必须到选定服务商当前价格页核对。

### 端侧模型

最小链路：选择输入 → 本机推理 → 输出。可选 LiteRT、ONNX Runtime Mobile 等引擎。

关注模型许可证、量化、模型大小、内存峰值、首次加载、发热、目标芯片加速与不支持算子。不要用台式显卡表现推断中端手机表现。

验收：最低目标手机上测延迟、峰值内存和温度；断网时是否仍可用；云端方案检查取消后计费与连接是否真正终止。

## 10.9 支付、电商、会员订阅

**最小版本：** 测试环境中完成一笔订单，从创建到支付结果再到权益生效。

- 数字内容、实物商品等交易类型适用的支付规则不同，先看目标市场政策。
- 不以客户端“支付成功”回调作为唯一凭证；由后端验证平台订单、处理通知与幂等入账。
- 订单有待支付、已支付、关闭、退款等状态；退款和订阅取消也会影响权益。
- 增量：订单后端、支付 / Billing SDK、收据验证、通知、防重复扣费、账务对账。
- 不自己保存银行卡敏感信息；使用受支持的支付服务。

验收：重复回调不重复发放、断网支付后可恢复、退款收回权益、测试订单不混入真实收入。

参考：[Google Play Billing](https://developer.android.com/google/play/billing)。具体地区与交易类型规则以当前政策为准。

## 10.10 音视频、下载器、后台计时

**最小版本：** 选一个合法媒体源，前台播放、暂停、退出。

- 增量：Media3 播放器、媒体会话、缓存、音频焦点。
- 后台播放与普通后台任务不同，可能需要符合要求的前台服务与可见通知。
- WorkManager 适合可延后的可靠任务，不提供精确到秒的倒计时保证。
- 倒计时不要依赖“每秒把数字减 1”，应记录合适的目标时间或单调时钟差值，再据此计算显示。
- 下载关注范围请求、校验、剩余空间、网络变化、取消、版权与访问授权。

验收：来电 / 耳机拔出、锁屏、网络断开、进程重建、空间不足。参考 [Media3](https://developer.android.com/media/media3) 与 [WorkManager](https://developer.android.com/topic/libraries/architecture/workmanager)。

## 10.11 游戏

**最小版本：** 一个场景、一种操作、明确胜负、可重新开始。

- 引擎负责场景、渲染、输入、资源；Android 导出仍需要 SDK 与签名。
- 先在低端目标设备测帧率、发热与触控，不只在编辑器中测试。
- 原生库、引擎版本和插件需要兼容目标 API、64 位与 16 KB 页大小要求。
- 联网竞技需要服务端权威状态与延迟处理，不把全部判定交给可修改客户端。
- 素材许可、未成年人、广告与支付、国内发行资质等均可能影响发布路径。

参考：[Godot Android 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)、[Unity Android 构建](https://docs.unity3d.com/Manual/android-BuildProcess.html)。费用和授权按所选引擎当前条款核对。

## 10.12 网站包装、PWA、低代码

PWA 是具备部分应用能力的网站；Capacitor 等容器可以将 Web 界面与原生接口连接。它们可复用网页技术，但 APK 签名、硬件权限、系统返回键、文件选择和商店质量要求仍要处理。

先验证：离线页面、登录 Cookie、文件上传下载、摄像头、深链、Android 返回、支付与第三方跳转。不要只验证电脑浏览器页面能打开。

低代码工具在选型前确认：能否导出独立 APK？谁持有签名密钥？订阅到期后应用还能运行吗？数据能导出吗？自定义域名与市场发布受什么限制？

## 10.13 每种类型通用的扩展顺序

先做一条完整操作链，再补失败状态，再补数据保护，之后做真机与 Release 回归，最后才扩大功能。每引入一种外部服务，都更新预算、密钥管理、隐私说明和故障预案。
